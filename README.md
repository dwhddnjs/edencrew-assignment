# 국내 주식 관심종목 앱

Naver 금융 데이터를 사용한 관심종목 · 검색 · 종목상세 3개 화면 구현.

---

## 실행 방법

```bash
flutter pub get
flutter run
```

- **Flutter**: 3.47.3 (stable) / Dart SDK `^3.11.5`
- **확인한 기기**: iOS Simulator — iPhone 17 Pro (iOS 26.1)
- **웹(Chrome)에서는 동작하지 않습니다.** Naver endpoint가 CORS를 허용하지 않습니다.
- **폰트**: 스타터 제공 방식 그대로 사용 (`assets/fonts/` Noto Sans KR, `pubspec.yaml` 등록).

---

## 폴더 구조

```text
lib/
  main.dart                앱 진입점
  app.dart                 MaterialApp + 하단 탭 바 셸
  core/
    formatters.dart        숫자 · 등락 · 축약 · 날짜 포맷
  models/                  화면이 쓰는 도메인 모델
    stock.dart             종목 (id, symbol, name, market)
    quote.dart             시세 (현재가, 등락, 시가총액)
    daily_price.dart       일별 시세 한 행 + 기간 탭(ChartPeriod)
  data/
    naver_api.dart         endpoint 4개 HTTP 호출
    dto/                   endpoint별 응답 파싱
    stock_repository.dart  DTO → 모델 조립, 일별 시세 페이지 캐시
  state/
    favorites.dart         관심 목록 (3개 화면 공유 상태)
  features/
    watchlist/             01 · 관심
    search/                02 · 검색
    detail/                03 · 종목상세
    common/                화면 간 공용 위젯
  theme/                   디자인 토큰 (스타터 제공, 미수정)
```

**계층을 `data → models → features` 3단으로 나눈 이유.** Naver 응답 필드가 `nv`, `pcv`, `aq` 같은 축약형이라 그대로 UI까지 들고 가면 읽을 수 없습니다. `data/dto`에서 한 번 변환해 `models`의 이름 있는 필드로 바꾸고, 화면은 모델만 봅니다. endpoint 응답 형태가 바뀌어도 수정 범위가 `dto/` 안에서 끝납니다.

## 기술 선택과 이유

### 상태관리 — `ChangeNotifier`

화면 간 공유되는 상태는 **관심 목록 하나뿐**입니다. 나머지(검색어, 선택된 기간 탭, 정렬 기준)는 각 화면에 갇혀 있어 `setState`로 충분합니다. 공유 상태가 하나인 규모에 Riverpod · Bloc을 얹으면 코드보다 배선이 길어집니다.

`state/favorites.dart`의 `ChangeNotifier` 하나를 화면에서 `ListenableBuilder`로 구독해, 요구사항인 3개 화면 별 아이콘 동기화를 상태관리 패키지 없이 처리했습니다.

`StockRepository`와 `Favorites`는 `app.dart`에서 한 번만 만들어 아래로 내려보냅니다. 페이지 캐시가 저장소에 붙어 있어서, 상세 화면을 닫았다 다시 열어도 받아 둔 페이지가 살아 있습니다.

### 일별 시세 페이지 캐시

`sise_day.naver`는 한 페이지에 10거래일을 반환합니다. `1년` 탭은 25페이지가 필요하지만, 탭을 누를 때마다 전부 다시 받지 않습니다.

`stock_repository.dart`가 종목별로 받아둔 페이지를 보관하고, 기간 탭이 요구하는 페이지 중 **아직 없는 페이지만** 이어서 요청합니다. `1개월`(2p) → `1년`(25p)으로 넘어가면 23페이지만 추가로 받고, 되돌아오면 요청이 없습니다. 응답의 `lastPage`보다 큰 페이지는 요청하지 않습니다.

받아 둔 페이지는 "1페이지부터 여기까지 연속"이라는 형태라 `int` 하나로 충분합니다. 어느 페이지를 받았는지 `Set`으로 들고 있을 필요가 없습니다.

같은 종목의 요청이 겹칠 때(1개월 로딩이 끝나기 전에 `1년` 탭을 누르는 경우)는 뒤 요청을 앞 요청 뒤에 줄 세웁니다. 그러지 않으면 두 루프가 같은 진행 상태를 읽어 같은 페이지를 중복 요청합니다.

### 관심 목록 시세 조회

`polling.finance.naver.com/api/realtime`은 `query=SERVICE_ITEM:005930,000660` 형태로 여러 종목을 한 번에 받습니다. 종목 수와 무관하게 요청 1회로 관심 화면 전체를 채웁니다.

검색 화면에서 별을 누를 때는 시세를 받지 않습니다. 검색 결과 행은 시세를 쓰지 않고, 관심 화면에 들어올 때 한 번에 받는 편이 요청 수가 적습니다.

### 주요 패키지

| 패키지             | 용도                | 선택 이유                                                                                                       |
| ------------------ | ------------------- | --------------------------------------------------------------------------------------------------------------- |
| `http`             | HTTP 요청           | `dart:io HttpClient`로도 가능하지만 보일러플레이트가 늘어남. `MockClient`로 테스트에서 응답을 갈아 끼울 수 있음 |
| `html`             | 일별 시세 HTML 파싱 | endpoint 4번이 JSON이 아닌 HTML 반환. 정규식으로 표를 긁으면 페이지 구조가 조금만 바뀌어도 깨짐                 |
| `integration_test` | 실기기 통합 테스트  | Flutter SDK 내장이라 외부 의존성이 늘지 않음                                                                    |

차트 · 숫자 포맷 · 상태관리 패키지는 추가하지 않았습니다. 아래에 이유를 적었습니다.

### 차트 — `CustomPainter`

`features/detail/candle_chart.dart`에 직접 그렸습니다.

캔들 차트를 지원하면서 토큰 색과 시안 여백까지 맞출 수 있는 패키지는 많지 않고, 그리는 도형이 **심지 사각형 + 몸통 사각형** 두 개뿐이라 패키지를 얹는 편이 오히려 깁니다. 몸통 색은 `chartLineUp` / `chartLineDown` / `chartLineFlat`, 심지는 `chartBaseline`을 씁니다.

시가 = 종가인 날(도지)은 몸통 높이가 0이 되어 보이지 않으므로 최소 1px을 보장합니다. 캔들 몸통 폭은 `슬롯 × 0.6`이되 최대 12px로 제한해, `1개월`(20개)에서 지나치게 두꺼워지지 않게 했습니다.

차트 영역 높이는 시안 값인 200px로 고정했습니다. 세로 스크롤 안에서 높이가 유동적이면 캔들 간격이 기기마다 달라집니다.

### 숫자 포맷 — `intl` 없이 직접

`core/formatters.dart` 한 곳에 모았습니다. 필요한 건 천 단위 구분자, 부호 붙이기, `억`/`조` 축약 세 가지뿐이라 정규식 한 줄로 끝납니다. 로케일 데이터를 들고 오는 `intl`을 붙일 이유가 없었습니다. 모든 화면이 이 파일을 거치므로 표기 규칙이 한 곳에서만 바뀝니다.

### 디자인 토큰

`lib/theme/`은 **한 줄도 수정하지 않았고 토큰을 추가하지도 않았습니다.**

- 화면 코드에 색상 hex를 직접 쓴 곳: 0곳
- 화면 코드에서 `AppPalette`를 참조한 곳: 0곳
- 정의된 치수 토큰 14개 전부 사용

색상 토큰 중 `chartAreaUp/Down`, `chartAxisLabel`, `chartVolumeBar`, `price*Bg`, `feedbackWarning`는 쓰지 않았습니다. 모두 선택 항목(차트 영역 채우기 · 축 라벨 · 거래량 바)에 대응하는 토큰입니다.

글자 크기와 행간은 토큰으로 정의되어 있지 않아(`lib/theme/README.md` 참고) 시안에서 읽은 값을 각 위젯에 직접 적었습니다.

## 직접 판단한 부분

시안에 정의되지 않아 직접 결정한 항목입니다.

### 토스트 노출 시간과 퇴장 방식

**2초 후 자동으로 사라집니다.** 문구가 한 줄이라 읽는 데 2초면 충분하고, 바로 아래 목록에서 계속 별을 누르게 되는 화면이라 오래 떠 있으면 방해가 됩니다.

**연타하면 이전 토스트를 지우고 새로 띄웁니다.** 기본 `SnackBar`는 큐에 쌓여 순서대로 나오는데, 그러면 마지막으로 누른 종목이 아니라 몇 개 전 결과가 보입니다. 등록/해제 피드백은 마지막 동작만 의미가 있습니다.

### 시세를 못 받은 행의 정렬 위치

**항상 뒤로 보내고, 그 안에서는 가나다순으로 둡니다.**

비교할 값이 없는 행을 중간에 끼우면 목록 순서가 갱신될 때마다 뒤바뀝니다. 뒤로 몰아두면 시세가 도착하는 대로 제자리를 찾아 올라가고, 그 전까지 순서가 흔들리지 않습니다.

### 로딩 / 네트워크 에러

| 상황                | 화면                                                                     |
| ------------------- | ------------------------------------------------------------------------ |
| 관심 — 시세 수신 전 | 행의 현재가 · 등락 자리에 스켈레톤 바. 행 높이가 유지돼 목록이 튀지 않음 |
| 관심 — 갱신 중      | 기존 값을 그대로 두고 `RefreshIndicator`만 표시                          |
| 상세 — 최초 로딩    | 중앙 로딩 인디케이터                                                     |
| 상세 — 기간 변경 중 | 기존 차트 · 표 유지                                                      |
| 검색 — 요청 중      | 별도 표시 없음 (디바운스 300ms + 응답이 빨라 깜빡임이 더 거슬림)         |
| **요청 실패**       | 빈 상태 + **다시 시도** 버튼                                             |

에러 화면은 **받아 둔 데이터가 하나도 없을 때만** 띄웁니다. 이미 시세를 받은 뒤 갱신 한 번 실패한 경우라면 이전 값을 그대로 보여줍니다. 멀쩡히 보이던 화면을 에러로 덮는 편이 더 나쁩니다.

### 긴 종목명 오버플로

**한 줄 `ellipsis`** 입니다 (관심 행 · 검색 행 · 상세 헤더).

두 줄을 허용하면 행 높이가 종목마다 달라져 목록이 들쭉날쭉해지고, 시안의 행 높이(60)가 의미를 잃습니다. 종목명은 앞부분만 봐도 구분되고, 바로 아래 종목코드가 정확한 식별자 역할을 합니다.

요약 카드의 숫자만 예외로 `FittedBox`를 써서 줄입니다. 시가총액이 `1,517조`처럼 길어질 때 잘리면 값을 읽을 수 없기 때문입니다.

### 검색어가 매우 길 때 빈 상태 문구

**20자에서 자르고 `…`을 붙입니다.**

문구에 입력값이 그대로 들어가므로, 길면 빈 상태 영역을 덮고 화면 밖으로 흐릅니다. 20자면 어떤 검색어였는지 알아보기에 충분합니다.

### Figma와 다르게 구현한 부분

치수와 타이포는 시안을 393x852로 렌더해 잉크 위치를 재고 맞췄습니다. 그래도 남은 차이가 셋 있고, 모두 제공된 에셋으로는 재현할 수 없는 것들입니다.

**아이콘 모양** — 시안은 선 굵기 1.5 정도의 얇은 아웃라인 세트입니다. Flutter 기본 `Icons`(Material)는 같은 자리에서 획이 더 굵습니다. 헤더 화살표는 모양이 같은 `Icons.south`로, 새로고침은 직접 그려 시안과 맞췄고, 별 · 돋보기 · 체크는 잉크 크기만 맞춘 상태입니다.

**숫자 폭** — 시안의 숫자는 Noto Sans KR이 아닙니다. 같은 줄에서 한글은 11에 정확히 맞는데 종목코드만 12.4에 해당하는 폭이고, 등락 문자열(`-400 (-0.22%)`)은 반대로 Noto 11보다 좁습니다. 한 크기로 맞추면 다른 문자열이 어긋나서 제공된 폰트의 원래 크기(11 · 15)를 유지했습니다.

**탭 바 아래 여백** — 시안 프레임은 탭 바 아래를 40.5 비워 두는데 실기기 안전영역은 34입니다. 그대로 두면 탭 바와 가운데 정렬된 빈 상태가 시안보다 4 정도 내려가서, 시안 값(40.5)을 최소값으로 잡았습니다.

## 막혔던 지점

### 1. 일별 시세 HTML의 한글이 깨짐

- **증상**: `sise_day.naver` 응답을 `utf8.decode`하면 한글이 전부 깨짐.
- **원인**: 이 페이지만 EUC-KR입니다. 그런데 Dart 기본 코덱에는 EUC-KR이 없습니다.
- **찾아본 것**: `charset_converter`는 플랫폼 채널이라 `flutter test`에서 못 돕니다. `enough_convert`는 big5 · gbk · koi8 · latin · windows만 내보내고 EUC-KR이 없습니다.
- **해결**: `latin1.decode(bytes, allowInvalid: true)`로 바이트를 1:1 대응시켜 읽습니다. 이 페이지에서 **읽어야 하는 값(날짜 · 가격 · 거래량 · 페이지 번호)이 전부 ASCII**라 한글이 깨져도 상관이 없습니다.

  안전한 근거: EUC-KR / CP949의 한글은 선행 바이트 `0x81~0xFE`, 후행 바이트 `0x41~0x5A` / `0x61~0x7A` / `0x81~0xFE`로만 이루어집니다. `<`, `>`, `"`, `/`, 숫자(`0x30~0x39`)는 그 범위 밖이므로 **깨진 한글이 태그나 숫자로 잘못 보일 수 없습니다.** 의존성을 늘리지 않고 끝냈습니다.

### 2. 요청은 200인데 내용이 에러 페이지

- **증상**: `curl`로 `sise_day.naver`를 부르면 상태 코드는 200인데 본문이 "페이지를 찾을 수 없습니다"였습니다. 상태 코드만 보면 성공이라 원인을 한참 못 찾았습니다.
- **원인**: User-Agent가 없으면 에러 페이지를 돌려줍니다.
- **해결**: HTML을 받는 경로에만 브라우저 User-Agent를 붙였습니다. JSON endpoint들은 필요 없어서 건드리지 않았습니다.

### 3. 관심 등록 직후 새로고침이 무시됨

- **증상**: 별을 누른 뒤 새로고침을 하면 시세가 갱신되지 않고, 테스트 2개가 실패했습니다.
- **원인**: `toggle()`이 `refresh()`를 fire-and-forget으로 호출하고 있었습니다. 그 요청이 끝나기 전에 들어온 다음 `refresh()`가 `_loading` 가드에 막혀 그냥 return됐습니다.
- **해결**: `toggle()`을 시세를 건드리지 않는 순수 동기 함수로 되돌렸습니다. 검색 화면은 시세를 쓰지 않고 관심 화면이 들어올 때 한 번에 받으므로, 애초에 여기서 받을 이유가 없었습니다.

### 4. 화면은 멀쩡한데 값이 안 채워짐 — `IndexedStack`

- **증상**: 검색 탭에서 담은 종목이 관심 탭에서 계속 스켈레톤으로 남았습니다.
- **원인**: 탭을 오가도 스크롤과 입력이 유지되도록 `IndexedStack`을 썼는데, 그래서 관심 화면의 `initState`가 **앱 시작 때 딱 한 번만** 돕니다. 그때는 목록이 비어 있어 `refresh()`가 즉시 return하고, 탭을 옮겨 와도 다시 돌지 않습니다.
- **해결**: 탭 전환 시 `refresh()`를 부릅니다. 화면을 살려 두는 선택의 대가라, 화면을 계속 살릴지 아니면 진입 시점을 잡을지 둘 중 하나는 명시적으로 처리해야 했습니다.

### 5. 지수가 섞여 오는 검색어에서 검색 전체가 실패

- **증상**: `코스피`, `달러`를 검색하면 결과가 안 나오는 정도가 아니라 화면이 빈 채로 멈췄습니다.
- **원인**: 자동완성 요청의 `target`에 `index`, `marketindicator`가 들어 있어 지수 항목이 섞여 오는데, 이 항목들은 `nationCode`가 `null`입니다. 이를 `as String`으로 받아 `type 'Null' is not a subtype of type 'String'`이 발생했습니다. 국내 주식만 남기는 필터가 있긴 했지만 **파싱이 필터보다 먼저**라 필터에 닿기 전에 터졌습니다.
- **해결**: 파싱 단계에서 nullable로 받습니다. 더해서, 화면에 `try/catch`가 없어 예외가 "항목 0개짜리 목록", 즉 백지로 보였던 것도 함께 고쳐 에러 상태를 띄우게 했습니다.
- **배운 것**: 목 응답에는 주식 항목만 있어서 테스트가 전부 통과했습니다. 이 일로 실제 API를 쓰는 통합 테스트를 추가했습니다.
